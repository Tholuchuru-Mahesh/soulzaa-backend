[Normal] 1. Introduction
[Normal] 1.1 Purpose
[Normal] Soulzaa is a global social entertainment platform that enables users to communicate, socialize, and earn through real-time voice, video, live streaming, gaming, gifting, and community-building features.
[Normal] The purpose of this document is to define the product vision, business objectives, organizational hierarchy, governance model, and high-level functional scope for the Soulzaa platform. This document serves as the foundation for all subsequent functional, technical, and implementation documents.
[Normal] 1.2 Product Description
[Normal] Soulzaa combines social networking, live entertainment, virtual gifting, gaming, and creator monetization into a unified platform capable of supporting millions of users worldwide.
[Normal] The application provides a secure, scalable ecosystem where users can:

[Heading 2] 1. Greedy Food
[Normal] Overview
• Real-time multiplayer game running 24/7.
• One global round for all users.
• Round: 30s betting + 10s wheel spin.
• Backend is authoritative for all results.

Betting Items
Veg: Carrot(5x), Corn(5x), Broccoli(5x), Tomato(5x)
Non-Veg: Burger(10x), Chicken(15x), Mutton(25x), Crab(45x)
Special Results (not bettable): Veg Salad, Non-Veg Salad.
Veg Salad pays all Veg bets. Non-Veg Salad pays all Non-Veg bets.

Rules
• Players may bet on one, many, or all 8 items.
• Chips: 100, 500, 1K ,x	10K, 50K.
• Bets lock immediately after placement.
• Coins are deducted instantly.
• No edit/cancel/refund/transfer.
• Last 8 results show only winning items.
• Top 3 winners shown with profile picture, username, amount won.
• Live winner ticker scrolls for all users.
• Personal history stores round number, bets, result, win/loss, payout.

Backend Logic
• After betting closes, calculate liability for all 10 outcomes.
• Carrot/Corn/Broccoli/Tomato pay only respective bets.
• Veg Salad pays all Veg bets.
• Burger/Chicken/Mutton/Crab pay respective bets.
• Non-Veg Salad pays all Non-Veg bets.
• Select outcome according to configured profit-protection business rules.
• Wheel animation is visual only and stops on backend-selected result.

[Normal] Backend Liability Calculation Engine
[Normal] Overview
[Normal] The Backend Liability Calculation Engine is the core decision-making system for all premium multiplayer games in Soulzaaa, including Greedy Food, Roulette, Lucky Fruit, and Phoenix vs Wolf.
[Normal] Its primary objective is to protect the platform's virtual economy by evaluating all possible outcomes and selecting a winning result according to the configured business rules.
[Normal] The client application must never calculate or influence the winning result. All calculations must be performed securely on the backend server.
[Normal] Platform Profit Protection
[Normal] The game engine must be designed to keep the platform profitable over time by evaluating payout liabilities for all possible outcomes and selecting the winning result according to the configured business rules.
[Normal] The backend should always ensure that the platform remains financially sustainable while still providing a fair and engaging gaming experience.
[Normal] This logic should remain configurable through the Admin Panel for future business requirements.
[Normal] Step 1 – Close Betting
[Normal] When the betting timer reaches 0 seconds:
[Normal] Stop accepting new bets.
[Normal] Lock all existing bets.
[Normal] Save all betting transactions.
[Normal] Retrieve all bets placed for the current round.
[Normal] No additional bets are accepted after this point.
[Normal] Step 2 – Calculate Total Bets
[Normal] The backend calculates the total Gold Coins placed on every betting option for the current round.
[Normal] Example:
[Normal] Betting Option	Total Bet
[Normal] Option A	1,000,000
[Normal] Option B	3,000,000
[Normal] Option C	2,500,000
[Normal] Option D	500,000
[Normal] The betting options differ depending on the game (Greedy Food, Roulette, Lucky Fruit, or Phoenix vs Wolf).
[Normal] Step 3 – Calculate Payout Liability
[Normal] For every possible winning outcome, calculate the total payout liability.
[Normal] The liability is the total amount the platform would pay if that outcome becomes the winner.
[Normal] Example:
[Normal] If Option A wins:
[Normal] Liability = Total Bet on Option A × Multiplier
[Normal] If a game contains grouped outcomes (such as Veg Salad, Small Lucky, or Number Groups), the backend must calculate the combined payout for all winning bets associated with that result.
[Normal] This calculation must be performed for every possible outcome.
[Normal] Step 4 – Compare All Liabilities
[Normal] After calculating every possible payout,
[Normal] the backend compares the liability of every outcome.
[Normal] Example:
[Normal] Possible Result	Liability
[Normal] Result A	5M
[Normal] Result B	12M
[Normal] Result C	18M
[Normal] Result D	8M
[Normal] Step 5 – Select Winning Result
[Normal] By default, the backend should select the winning result with the lowest payout liability, helping the platform remain profitable over time.
[Normal] The selected result is then stored as the official result for that round.
[Normal] The winning result must always be generated before the client-side animation begins.
[Normal] Step 6 – Generate Game Result
[Normal] Depending on the game:
[Normal] Greedy Food → Select winning food item or Salad.
[Normal] Lucky Fruit → Select winning fruit or Lucky result.
[Normal] Roulette → Select winning number (0–36).
[Normal] Phoenix vs Wolf → Select winning side, then generate valid card values matching that outcome.
[Normal] The generated result is sent to all connected players.
[Normal] Every player receives the same result.
[Normal] Step 7 – Start Result Animation
[Normal] After the backend has selected the winner:
[Normal] Send the result to all clients.
[Normal] Start the wheel, fruit, or card animation.
[Normal] Animation duration: 10 seconds.
[Normal] The animation must stop exactly on the backend-selected result.
[Normal] Animations are visual only.
[Normal] They never determine the winner.
[Normal] Step 8 – Settle Bets
[Normal] After the animation finishes:
[Normal] Calculate player winnings.
[Normal] Credit Gold Coins to winners.
[Normal] Record wallet transactions.
[Normal] Update player history.
[Normal] Update Top 3 Winners.
[Normal] Update Live Winner Ticker.
[Normal] Save round summary.
[Normal] Step 9 – Store Round Information
[Normal] Every completed round must be permanently stored.
[Normal] Store: Only for superadmin
[Normal] Round Number 
[Normal] Winning Result 
[Normal] Total Bets 
[Normal] Total Payout
[Normal] Platform Profit 
[Normal] Total Players 
[Normal] Top 3 Winners
[Normal] Wallet Transactions
[Normal] Timestamp
[Normal] This information is used for analytics, auditing, customer support, and dispute resolution.
[Normal] Security Rules
[Normal] All calculations must happen on the backend.
[Normal] The client application must never calculate the winning result.
[Normal] The client must never calculate payouts.
[Normal] Wallet balance must always be verified by the backend.
[Normal] Every bet must generate a transaction record.
[Normal] Every payout must generate a transaction record.
[Normal] Every completed round must be permanently stored.
[Normal] Every API request must be authenticated.
[Normal] All game events must be recorded in audit logs.
[Normal] All premium games (Greedy Food, Roulette, Lucky Fruit, and Phoenix vs Wolf) should use the same backend liability calculation engine. Only the betting options, multipliers, and UI animations differ between games. By sharing a common backend engine, the platform ensures consistent behavior, simplified maintenance, improved scalability, and reduced development effort.
